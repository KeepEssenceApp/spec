# UX mock

所有客户端的屏幕，摆在一张可以平移、缩放的大画布上。是讨论界面用的草图，不是实现。

## 打开

直接用浏览器打开 `index.html`。它是自包含的，不联网。

- 拖动平移；滚轮或双指缩放；双击一屏放大。
- 顶部的名字跳到对应的端；`0` 适应全部，`1` 原始大小。
- 地址后面加 `#life`、`#perm`、`#flows`、`#states`、`#kit`、`#iphone`、`#share`、`#shortcut`、`#android`、`#web`、`#ext`、`#mac`、`#eink` 直接打开那一端。

## 改

`index.html` 是生成的，不要手改。改源文件后运行：

```
python3 design/mock/build.py
```

| 文件 | 内容 |
|---|---|
| `screens_iphone.py` | iPhone App、分享入口、快捷指令 |
| `screens_android.py` | 安卓 App |
| `screens_web.py` | 网页 |
| `screens_capture.py` | 浏览器扩展、Mac 菜单栏应用 |
| `screens_eink.py` | 墨水屏 |
| `screens_life.py` | 一个条目的一生：七种条目 × 五个阶段 |
| `screens_more.py` | 设备权限、流程、状态、组件与样式 |
| `content.py` | 各端共用的示例内容（全是编的）和共用的组件：存入完的一句话、助手的一行、深读队列里的一条、条目的卡、解读、每日摘要的四部分、今日状态、接入（客户端的短码、允许页、设备列表；助手的产品列表、步骤、接入地址）、深入对话（面板、一份精读、开场话、助手那边的对话、把结果贴回来） |
| `mocklib.py` | 设备外框、图标、logo |
| `mock.css` | 界面和画布的样式，颜色在 `.ui` 和 `.ui.dark` 里；组件板上的色值直接读自这里 |
| `canvas.js` | 平移和缩放 |

## 加一屏

在对应的 `screens_*.py` 的列表里加一项，然后重新生成：

```python
phone("屏幕名", "一句话说明", "<这一屏的 HTML>", tab="home", title="标题")
```

外框函数：`phone`、`android`、`webapp`、`browser`、`macdesk`、`eink`。加一个端：在 `build.py` 的 `SECTIONS` 里加一行。

## 规则

界面照 [`product/`](../../product/README.md) 画，视觉照 `brand/visual.md`（品牌资料暂未公开）。logo 和字标直接取自 `brand/logo/`，不改形状；线的颜色跟着所在位置的文字颜色走，圆点保持金色。

- 同一个东西在各端用同一个组件、同一句话：先看「组件与样式」板，没有的先加到板上再用。
- 所有的字和它的底至少 4.5:1（大字 3:1），深色也一样。
- 界面文字只用 [词表](../../product/glossary.md) 的「对外叫法」：条目、存入、收藏、解读、精读、深入对话、笔记、每日摘要、助手、月历。不出现蜜蜂的词。代码里的名字（`bee_chip`、`hive`、`honey`）是内部词，不改。
- 金色只给留下来的东西：笔记、「值得深读」、没读的每日摘要、月历里留下了笔记的那一天。按钮、链接、选中状态用黑白。
- 别的 App 只画中性的通用形状，不画真实产品的图标；产品名只以文字出现。
- 每种条目用同一副骨架：条目的卡用 `stage1`，解读用 `drop`，不为某一类内容单画一种样子。
- 有底或有框的只有能按的东西（按钮、输入框、选择）。状态和判定不画底、不画框，是一个圆点加字（`.pill`）：灰圈是还在等，灰点是在准备，黑点是好了，金点是留下来的，金圈是值得深读，小灰点是略过或已移出。类别（`kind_pill`）只有字，没有点。
- 进来的每一样东西叫「条目」，存入这个动作叫「存入」：条目缺省 30 天到期删除，所以不叫收藏。「收藏」是另一个动作：把一个条目的期限延到不过期（`life_pick` 的最后一档，`kept()`），不用精读也不用深入对话。收藏的条目还是条目，不是笔记，在「今天 › 全部」里用「收藏」筛出来。「内容」只指原文的正文（没取到内容、内容和解读已删除）。
- 读的深度有三层，一层一个词，不混用。解读：每条都有，助手自动做。精读：深读队列里的条目，定时来的助手趁它排着自己读透，交回一份精读（`read_page`）；它跟着队列里的这一条走，不是笔记。深入对话：用户带着这一条去助手那边，聊、让它再查、跑它那边的操作，画在助手那边（`assist_chat(msgs=CHAT_DEEP)`）。不用「细读」「细聊」「深入对话请求」这些词；清单叫「深读队列」，按钮只有「加入深读队列」「看精读」「去深入对话」。
- 助手那边做了什么我们看不到，所以没有「深入对话中」「已完成」这类状态。队列里一条的状态只用 `RIPEN` 里的五个：等精读、精读中、精读好了、没做精读、已移出。去没去深入对话只照实写成一句话（哪天去过、有没有笔记回来）。有笔记回来就移出队列；用户可以自己移出；7 天没动静移出。点「深入对话」出来的面板用 `dig_pick`。
- 手机上一个条目（解读、每日摘要里的一条）可以左右滑，只有两个动作：往右加入深读队列，往左不感兴趣。用 `swipe(card, "dig")`、`swipe(card, "no")` 画滑到一半的样子，做完的一句话用 `said_undo()`。加入深读队列用黑底，不感兴趣用灰底，都不用金色。网页和墨水屏没有滑动。
- 通知只有一种：条目解读好了。句子用 `NOTE_ONE`、`NOTE_MANY`、`NOTE_MISS`，判定在前，标题在后；连着解读好的合成一条。别的事（每日摘要出了、条目快要到期删除、助手没来）不画通知。设置只有一项三选一（`notify_card`），并照实写这台设备收不收得到。系统的权限提问只出现在用户点了「通知我」之后。只存入档的入口（快捷指令、扩展、Mac 菜单栏）的通知只说存入的结果，不说解读。
- 条目的状态用 `cell()`，照 logo 的读法，一堆形状进来，留下一个金点：三个空心的形状（三角、方块、圆）是等分派，三个实心的形状是等解读，一个黑点是已解读，金圈是值得深读，金点是留成笔记。笔记的那一行用 `note_thumb()`。
- 助手的名字只在 `content.py` 里定：`SCOUT`、`SIPPER`、`RIPENER`。
- 接入分两种。我们自己的客户端（手机 App、浏览器扩展、Mac 应用、快捷指令）显示短码（`join_wait`），KeepEssence 里核对后允许（`join_allow`）。助手不用短码：在产品列表（`product_list`）里选，照步骤（`guide`）把接入地址贴到它那边，再在允许页点允许（`join_allow(product=…)`）。
- 助手有两种，每一行都标出来（`kind_pill`）：「定时来的」能解读、汇总、精读，也能深入对话；「对话里的」只能深入对话。
- 界面上不出现任何凭据。能复制的只有三样：接入地址（`addr_box`）、深入对话的开场话（`opening_box`）、月历图片的地址。
- 助手那边的对话用 `assist_chat` 画成中性的聊天界面，外框加 `other`（`screens_iphone.other`）标明不是 KeepEssence 的界面；不仿任何真实产品。
- 导航只有四项、顺序固定：今天、每日摘要、笔记、助手设置。手机底栏、安卓底栏、网页左栏一致。读档的设备没有「助手设置」：`phone(..., reader=True)`、`webapp(..., reader=True)`。
- 月历用 `hive(days)` 画：一天一个圆点，每行七个，状态 0 到 4。只作「今天」页的背景（`bg=hive_bg()`）和点开后的大图（`hive_page()`）。没有东西可列时用 `empty()`，只有一句话，不画插图。
- 月历的图片（给别处嵌入的那张）用 `hive_img()`：只有圆点和数字，不带任何内容。
