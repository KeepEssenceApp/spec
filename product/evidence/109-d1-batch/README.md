# 109-d1-batch：D1 batch 保证什么、不保证什么（本地实测）

[techspec](../../techspec.md) §11「D1 batch 能保证什么，不能保证什么」和 [acceptance](../../acceptance.md) K27 的 g–l 引用的实验。**只放测试脚本和结果**：没有业务实现，不是任何仓库的代码，不进发布。

## 载体：本地，不是线上 D1

- **Miniflare 的本地 D1**（workerd + SQLite），用 wrangler 4.167.0 的 `getPlatformProxy` 打开，内存库（`persist: false`）。
- **不是线上 D1，也不是线上的测试库。** 脚本不连 Cloudflare，不读任何密钥，不写任何远端。
- 所以这里的结果只证明「本地 D1 这样」。线上 `batch()` 的 `meta.changes`、「后一条读得到前一条的写」、并发下只有一个赢家，**线上没有实测**，是 K27 m 的事，而 m 要先问 Cheney（远端 D1 操作，和迁移是同一道门，E7）。没有授权之前，K27 的 g、h、k 只算本地结果。

## 怎么重跑

需要 Node 22 或更新（CI 用 22；最近一次在 v24.14.1 上跑）。

```sh
cd product/evidence/109-d1-batch
npm install      # wrangler 固定在 4.167.0；它自己把 miniflare、workerd 也钉成精确版本，所以不放 lockfile
npm run check    # 逐项打印，末尾 [OK] 或 [MISMATCH, expected …]；有一项不符，退出码是 1
```

`npm run check` 会把输出重写进 `last-run.txt`，开头几行带运行时间、wrangler 和 node 的版本。`node_modules/` 和 `.wrangler/` 不进库（`.gitignore`）。路径都是相对脚本自己的，没有写死本机路径。

## 结果

`last-run.txt`：2026-11-27 11:20:03 UTC（悉尼 22:20），wrangler 4.167.0，node v24.14.1，**26 项，0 项不符**。

每一项都带着它必须得到的值。这是这一版新加的：上一版没有期望值，T3 里「重复 `request_id` 的普通 INSERT 应该被唯一约束拒掉」那一项其实报的是 `no such column: tokens_dummy`（第一条语句写错了列），根本没走到唯一约束，却没有人看出来。现在 T3 报的是 `UNIQUE constraint failed: usage_records.request_id`，并且要这句话出现才算过。

## 每个 T 对应 K27 的哪一项

| T | 验什么 | K27 |
|---|---|---|
| T1 | 对照：前一条 `UPDATE … WHERE` 一行没改到，无条件的后一条 INSERT 照样写进 1 条 token（batch 不是 fence） | g 的反面（为什么每条语句要自己带条件） |
| T2 | 后一条用 `changes() > 0` 带条件：前一条没改到行，不写（token 0 条）；改到了，写（1 条） | g（`changes()` 的写法；规格要求实现不依赖它，见 T10） |
| T3 | 同一个结果批发两次，第二次两条都是 0 行、token 仍 1 条；不带 `OR IGNORE` 的重复 `request_id` 被唯一约束拒掉，token 仍 1 条 | j（回包丢了的重试）；i（约束） |
| T4 | 一批里后一条违反唯一约束：整批回滚，前一条的状态变更也不留 | i |
| T5 | 占用一次机会：5a 对照（回收写不带条件，间隔没到也误回收 2 行）；5b 带「计数已是 n+1」的条件，间隔没到时 0 行；5c 间隔到了才是 1 行加 2 行 | h |
| T6 | 20 个并发的「占用一次机会」，恰好 1 个改到 1 行，最终 `started` = 2 | k |
| T7 | 30 个并发的占位抢「每次尝试 3 行」，恰好写进 3 行 | k；「占位和结算」里的原子占位 |
| T8 | 结果写和回收写，两种发出顺序各 100 轮：带用量的两种顺序都落到「带用量、token 1 条、预算占 1」；没有用量的，结果先到是「没有用量、预算放掉」，回收先到是「已回收、预算不放」；没有第三种状态 | l；a（正常超时）、b、c、d（正常结算与迟到的结果） |
| T9 | 回收之后迟到的带用量写两次：「带用量」、token 1 条；迟到的没有用量：0 行、仍是「已回收」 | b、c、j |
| T10 | 不用 `changes()`，用 `EXISTS` 加唯一约束加 `OR IGNORE`：两种发出顺序各 100 轮同 T8 的带用量那一行；已经「没有用量」收了尾的行再来一个带用量的写：0 行、token 0 条 | g（规格要求的写法）；l；d |
| T11 | 迁移的形状：旧行不带请求号，唯一索引只对有请求号的行生效；同一个请求号写第二次被忽略 | 「迁移当天」里账的形状。**只是形状**：预算怎么按旧行 `calls` 的总和算，这里没有测 |

techspec §11「本地实测」的 ①–⑨ 对应脚本的 T1–T9，⑩ 对应 T11，② 里 EXISTS 那一半是 T10。

## 这里没有的

- K27 m：线上 D1 的测试库。没跑，要先问 Cheney（E7）。
- K27 e（回收后原进程再占位被拒）、f（四个切点后下一个 Cron 发 0 个请求）、四个切点本身、迁移当天的预算算术（`SUM(calls)`）：这里没有测，它们要在实现出来以后用核心加模型替身测。
- Worker 在 batch 提交之后、回包之前被回收的情形（techspec §11 同一节写了它怎么按账处理）。
