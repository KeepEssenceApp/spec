# 规则

必须遵守。一个功能守不住规则就不做，不改规则。

## 总则

产品的内核是「AI根据你的需求，帮你筛选，为你内化」。任何功能要么帮助筛选，要么帮助内化，要么让这两件事更贴合用户的需求；三者都不沾的不做。

## 一、产品

| # | 规则 |
|---|---|
| A1 | 不做记事本：不提供给用户按条件过滤、分类、翻找旧内容的入口。条目、解读和每日摘要没有搜索；只有留下来的笔记可以快速查找。 |
| A2 | 条目和解读到期后，对用户一律是删除，看不见；内部归档，保留规则由配置决定，对外说明见 数据保留说明（尚未发布）。每日摘要和笔记不过期。 |
| A3 | 用户没有必须做的动作。能做的只有：读了、深挖、不感兴趣、看过了、挽回、把深挖的结果贴回。不理就等于放弃，不留待办。 |
| A4 | 攒存的条目进到每日摘要全自动；深挖只由用户手动发起，系统和助手都不自动发起。 |
| A5 | 没有助手在干活就没有产出，这不算故障；但必须让用户看得出来：读的平台每个主要页面常驻状态栏。 |
| A6 | 标签不成为用户的负担：不显示、不需要用户打、不让模型自由造词。 |
| A7 | 每日摘要不含大段原文，不嵌图片，不带标签；固定四部分：总结、值得深挖的、其余的、睡前一问。 |
| A8 | 简单优先：没起到明显作用的不做；选项要少，界面不堆东西。 |
| A9 | 概念命名只用 [词表](glossary.md)。界面和对外文字只用词表里的中文词，不用比喻。 |
| A10 | 原型（AllKeep）只是参考：不照搬结构和接口，不以兼容它为约束，不承诺迁移它的内容和标签。 |
| A11 | 所有类型的条目用同一套结构；解读固定四项。不为某一类内容单做一种样子。 |
| A12 | 解读一交回用户就能读、能处理，不必等每日摘要。 |
| A13 | 不显示链接串和抓取的残片；没取到内容就照实说，不拿残片凑。 |
| A14 | 月历不催人：没有连续天数、断签提示、提醒、排名。它也不是找东西的入口：不显示标题，不能翻到条目。 |
| A15 | 公开的月历图缺省关闭；图里不得有任何内容或身份信息，只有圆点标记和数字。地址猜不到，可以换、可以关。 |
| A16 | 推送只说一件事：核心内置助手完成了某条的解读或精读，可以继续做下一步。初筛（分派助手给条目打标签）完成不发通知。只发给用户的设备，不发给助手；用户自带助手的动作，以及任何助手的内部动作（认领、交回、续期），一律不推。同一批完成合并为一条，不重复、不催、不带数字角标；用户可以关。 |

## 二、攒存的平台

| # | 规则 |
|---|---|
| B1 | 攒存是一个动作，界面上叫「存入」：触发，继续做手上的事，完成时一句话。不换应用，不弹需要再点一下的窗口。 |
| B2 | 不说比事实多的话：核心收到了才说已存入；排着队就说排着队；没存入要说原因。 |
| B3 | 重复的吞掉，不新增。用户自己触发的给一句反馈，自动行为不出声。 |
| B4 | 像密码的内容不悄悄上传，也不悄悄丢掉：先问用户。 |
| B5 | 应用不抢键盘，不自己跑到前台。弹提问、开网页只能是用户刚亲手点了什么的结果。 |
| B6 | 权限提问最少，并照实告诉用户第一次会问几次、问什么。 |
| B7 | 攒存的请求不带标签，也不带任何初筛信息。 |
| B8 | 对用户而言接入只有一个动作：在 本产品 的页面上点允许。界面上不出现凭据，不让用户看、复制、手填凭据。客户端核对一个短码；助手走 OAuth 的允许页。接入地址、深挖的开场话、月历的图片地址不是凭据，可以复制。 |
| B9 | 每个接入的客户端和助手都是一个有名称的设备，用户随时可以单独撤销，立即生效。不为防用户自己破解做额外设计。 |
| B10 | 客户端的权限分三档：只存入、读、管理。授权时由用户定，可以调低，不能调到比对方请求的高。至少保留一台管理档的设备。 |
| B11 | 界面按权限裁剪：没有权限的入口不显示。 |

## 三、核心与契约

| # | 规则 |
|---|---|
| C1 | 核心是唯一说了算的地方：是不是重复、算不算攒存成功、什么时候过期、活归谁，都由核心答。 |
| C2 | 契约先写，核心和各平台都照契约做。平台之间互不知道对方存在，平台只知道它该知道的。 |
| C3 | 共用的规则只有一份：密码识别、各状态的措辞、错误码，各平台从契约同一处拿。 |
| C4 | 已发布的客户端不被悄悄弄坏：核心一直认旧版本，直到走完弃用步骤。 |
| C5 | 寿命、上限、认领过期由核心执行，不依赖任何助手。 |
| C6 | 核心对公网开放，只走 HTTPS；认证、限速、每个设备的权限范围都必须做。 |
| C7 | 按多用户设计：所有数据按用户隔离。 |
| C8 | 契约里不出现产品名，不出现任何一个助手的名字。 |

## 四、助手

| # | 规则 |
|---|---|
| D1 | 助手通过 MCP 接入，可以换。核心只有一套给助手的契约，分派助手和工作助手也用它，没有后门。 |
| D2 | 助手自己来取活。核心不依赖推送；可以对能接提醒的助手发不带内容的「有活了」。 |
| D3 | 「有没有活」必须能用一个不经模型的普通 HTTP 请求问到。 |
| D4 | 一份活同时只归一只助手（认领）；认领会过期；同一份活交两遍不出乱子。 |
| D5 | 每个产物署名：由哪只助手做的。 |
| D6 | 核心只存最终产物。深挖的过程留在助手那边。 |
| D7 | 助手只能做契约允许的事：不能删东西、管设备、改规则、把寿命改到上限以外、自己发起深挖。 |
| D8 | 分派助手免费；工作助手在内测期间不收费，正式推出后收费；用户自带的助手免费。自带助手接入不能比用工作助手难。 |
| D9 | 助手授权后持有可自动续期的凭据，不需要用户经手，不需要定期重新授权，可单独撤销。不提供固定凭据这条路。 |
| D10 | 用户接入一只助手时，明确告诉他：内容会被送到这只助手运行的地方。 |
| D11 | 助手按能力分两类：定时型可以解读、汇总、深挖；对话型只能深挖。不按品牌给助手开特例。 |
| D12 | 笔记只在用户明确说出之后存回；助手不能写时由用户贴回。开场话不带内容，内容只经 MCP 取。 |
| D13 | 接入指南只写查实过的步骤；没查实的产品显示「待验证」，不编步骤。 |

## 五、工程与运行

| # | 规则 |
|---|---|
| E1 | 凭据和密码不进聊天，不进仓库。 |
| E2 | 说「验证过」要说在哪验证的（真机、模拟器、推断）；没验证的照实列出。 |
| E3 | 踩过的坑写进对应平台目录的文档。 |
| E4 | 模型的钱要有数：不让机器空转；分派助手的费用按用户设上限。 |
| E5 | 数据是用户的：拷线上数据要用户同意；截图和演示用编的内容。 |
| E6 | 谁能注册、谁能进来由 Cheney 定。v1.0 关闭公开注册。 |
| E7 | 动用户的设备、改线上设置、删数据（按寿命到期自动删除除外），先说再做。 |
