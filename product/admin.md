# 管理后台

状态：2026-11-25 定。给运营者（部署这套服务的人）用的后台，地址是单独的子域名（官方部署是 `admin.keepessence.app`）。它不是用户的界面，用户看不到它。

## 原则

- **不看内容。** 数据是用户的（规则 E5）。后台只显示数量、时间、设备和助手的名称，不显示任何条目、解读、每日摘要、笔记的标题或正文。唯一的例外是反馈：那是用户写给运营者的话。
- **谁能进由运营者定**（规则 E6）。后台是执行这条规则的地方：邀请、停用、删除都在这里。
- **会丢东西的事先确认。** 删除账户要输入对方的邮箱确认；停用可以恢复。
- **每个动作留记录。** 谁在什么时候对谁做了什么，在后台里能查。
- 界面沿用同一套颜色和用词（`design/tokens.css`、`design/terms.md`）。金色不用在后台里：这里没有「留下来的东西」。红色只给删除和停用。

## 登录

一个运营者口令。登录后是有期限的会话（12 小时），存在只有服务器能读的 cookie 里。连续输错会被限速。口令不写进代码，放在部署平台的密钥里。

## 页面

| 页面 | 内容 | 动作 |
|---|---|---|
| 概览 | 报名多少人、邀请了多少、多少人已加入、近 7 天活跃多少；今天和近 7 天的存入、解读、每日摘要、笔记数量；等着初筛和解读的条数；内置助手今天和近 7 天用了多少 token；定时任务上一次什么时候跑的；发信和通知有没有配好 | 无 |
| 报名名单 | 落地页的内测报名：邮箱、从哪个语言的页面来、现在用什么工具、从哪里收集、常用助手、想用的方式、最头疼的事、报名时间；每人的状态：新报名、已邀请、已加入 | 按状态和语言筛选、查找、邀请一个或勾选多个一起邀请、下载表格 |
| 邀请 | 邀请名单：邮箱、邀请时间、加入时间 | 加一个或粘贴一批邮箱、撤回还没加入的邀请、取登录验证码（没配发信服务时用；显示一次，可复制） |
| 用户 | 每个账户：邮箱、加入时间、上次活跃、状态、设备数、助手数、现有条目数、笔记数、占用空间 | 查找；点开看详情 |
| 用户详情 | 设备（名称、种类、档位、上次使用）、助手（名称、类型、干哪几步、上次来的时间）、近 30 天每天的数量、各助手的用量 | 停用和恢复、让全部设备退出、撤销单个设备、删除账户 |
| 用量 | 内置助手每天的调用次数和 token；另有「费用未知的调用」，分两类列出：「已经发出、没拿到用量」（核心看到了结局、结局里没有用量：超时、连接断开、错误状态、200 没有用量）和「没有结果，不确定发没发出，按已花掉计」（记了但可能没发出去、被回收、写结果失败）；两类都不折成 token，不写成「供应商没收费」，不写成「0 费用」，第二类不说请求已经发出、也不说已经收费；用得最多的账户 | 选天数 |
| 反馈 | 用户在应用里写给运营者的话：谁写的、什么时候、在哪个端、当时在做什么、哪里不对劲、希望怎样；配了转发的话，每条对应的 issue | 打开对应的 issue、点开写的人 |
| 系统 | 存入的链接怎么读：直接读、读取服务（Jina Reader、Firecrawl，或接口相同的自建服务）各自开没开、地址、有没有密钥、先后顺序；每种方式上次试读的结果；近 7 天按平台（微信公众号文章、小红书、其余的）和读到它的方式统计的数量，其中读视频里的话的另算：读成了几条、没读成几条（没话语、太长、没取到）。不记网址，不记账户 | 打开或关闭一种读取服务、填地址和密钥（密钥只能填，不再显示）、调顺序、用某一种方式试读一个网址 |
| 记录 | 后台里做过的动作，新的在前 | 无 |

## 各个动作的确切含义

| 动作 | 效果 |
|---|---|
| 邀请 | 邮箱进邀请名单，可以登录。报名名单里那一行记下邀请时间。不发邮件（没配发信服务时） |
| 撤回邀请 | 还没加入的：不能再登录。已经加入的账户不受影响，要拦人用「停用」 |
| 停用 | 这个账户的所有设备和助手立刻不能用，不能再登录；数据原样留着；内置助手不再为它干活。可以恢复 |
| 让全部设备退出 | 撤销这个账户的所有客户端设备；助手不动。他可以再登录 |
| 删除账户 | 账户和它的全部数据（条目、解读、每日摘要、笔记、附件、设备、助手）一并删除，不能恢复。邀请也一并撤回 |

## 不做

- 不能替用户登录，不能看或改用户的内容。
- 不发邮件、不群发通知。
- 多个运营者、分权限：以后再说，现在只有一个口令。

## 接口

后台自己是一个独立的部署，经核心的管理接口取数据和执行动作；报名名单在官网的数据库里，后台直接读它。管理接口不在契约里（契约只管客户端和助手），用运营者密钥保护。
